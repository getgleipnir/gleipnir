# Third audit: mandate spec 0.3 (24.10.2026)

An independent reviewer audited `spec/mandate.md` 0.3, the Python reference (`gleipnir_verify.mandate`), the TypeScript port (`@getgleipnir/verify/mandate`), the CLI, the reference HTTP checker and both MCP servers, at commit `e1afe16`. Every attack was written as a test that asserted the vulnerable behaviour; 17 of 19 findings reproduced, the rest were found by reading code or the spec. Regression tests: `python/gleipnir-verify/tests/test_mandate_audit3.py`, the `A3_*` and problem-string cases in the shared vectors, and the CLI/HTTP tests named `audit3`.

| id | sev | component | finding | status |
|---|---|---|---|---|
| F1 | high | HTTP `/revoke` | Anyone could store self-signed junk revocations, filling the store so a real revocation was refused, and bloating the state every request re-reads | Fixed: `/revoke` takes the mandate with the revocation and stores it only if it counts (signed, aimed at that mandate or a link, by someone who may revoke it), at most 4 KiB (`Checker.revocation_counts`) |
| F2 | medium | resolve (Py, TS) | A re-check after an override that failed before the claim step left the payment id claimed forever | Fixed: a taken-over claim is always settled; a re-check that stops on `checker_unavailable`, `status_unavailable` or `ledger_missing` puts the escalation back |
| F3 | medium | spec 7.1, resolve | A `signer_unknown` waiver vouched for everyone unknown at re-check time, including people offboarded since | Fixed: escalations name the unknown people (`unknown`); the waiver vouches for exactly those (`vouched`) |
| F4 | medium | payment log key | Keyed by the mandate's own `company` text: two mandates of one customer could pay one invoice id twice | Fixed: `holds` returns the bank's customer id; the log is keyed by `[customer, id]` |
| F5 | medium | authority contract | No canonical person: aliased ids with two keys counted twice | Fixed: `AuthorityResult.person`; distinct persons are counted for thresholds, joint rules and company overrides |
| F6 | medium | receipts | Override signer identities, and dropped mandate co-signatures, were not bound: a receipt could be relabeled | Fixed: decisions record `signers` and `approvers`; receipts report those and require a valid signature for each |
| F7 | medium | status fetcher | DNS-rebinding TOCTOU between the address check and the connection | Fixed: resolve once, require every address public, connect to that address with SNI and certificate check for the name; port 443 only |
| F8 | medium | status fetcher, HTTP checker | Per-read timeout only: a dripping server held the global lock for days | Fixed: one deadline for the whole fetch (watchdog), and the reference checker fetches status before taking its lock |
| F9 | medium | Py vs TS | Nesting depth limits differed (Python recursion limit vs 900) | Fixed: explicit depth limit 32 in both, in the spec (section 13), with a vector |
| F10 | low | spec 4.2 | A holder can strip a co-signature of a rejected signer; the hash stays the same | Documented: the presented, counted set decides, and the decision records it (F6) |
| F11 | low | spec vs code | `signer_unknown` did not hold the id though the spec said so | Spec corrected; only `over_payment_limit` (and override blocks) hold the id |
| F12 | low | spec 7.1 | `ledger_missing` overrides could never succeed | Fixed: `ledger_missing` and `checker_unavailable` are not overridable (`override_not_authorized`) |
| F13 | low | company override | Count ignored the joint rule of the mandate's own signers | Fixed: needed = threshold and the joint of everyone who signed the mandate or the override |
| F14 | low | HTTP checker | 3000 valid self-made co-signatures cost 0.55 s of verification per request | Fixed: at most 16 signers per mandate and 16 signatures per override |
| F15 | low | Py vs TS | Link company match: `ids: null` vs absent, `true` vs `1` | Fixed: exact JSON equality in both; absent is not null |
| F16 | low | Py vs TS | Problem strings quoted differently | Fixed: Python `repr` quoting in TS; problem strings are in the shared vectors |
| F17 | low | TS MCP | Prototype-named arguments (`constructor`, `__proto__`) were accepted | Fixed: own-property checks |
| F18 | low | dev file state | Truncate-then-write was not crash-safe | Fixed: separate lock file, write to a temp file, fsync, atomic replace; nothing written on error |
| F19 | info | spec | Payee name not bound; status replay window; waiver chaining; company override exceeding a delegated cap | Window now runs from the first escalation; company waivers lift only the mandate's own period limit; payee name and status replay window documented as residual risks |

The reviewer also confirmed, among others: forged or altered objects, key-type confusion, passkey domain separation, override replay across payments and mandates, concurrent overrides, period-ledger rollback and aggregation, account canonicalization (26 variants agree across both implementations), period keys (20 000 instants agree), status freshness and signer rules, retired keys, request smuggling and body limits on the HTTP checker.
