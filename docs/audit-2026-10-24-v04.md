# Fourth audit: mandate spec 0.4 (24.10.2026)

An independent reviewer audited the 0.4 additions at commit `390ae8f`: ISO 20022 pain.001 building and checking (`gleipnir_verify.iso20022`, the TypeScript `pain001Problems` and its XML reader), revocation lists, bank key sets and closed shapes. Every attack was written as a test; 4 of 5 findings reproduced as failing tests, the fifth as a Python/TypeScript differential. Regression tests: `python/gleipnir-verify/tests/test_mandate_audit4.py`, the new `pain001` and `feed_*` cases in the shared vectors, and the lone-surrogate test in `mandate.test.ts`.

| id | sev | component | finding | status |
|---|---|---|---|---|
| F1 | high | pain.001 check (Py, TS) | Only the transaction with the payment's end-to-end id was checked: a second transaction (or a second `PmtInf`) to another account passed; `NbOfTxs` and `CtrlSum` were not checked | Fixed: the whole message must be what the mapping writes for this payment, except names, ids, dates and remittance text (`unexpected_content`, spec 6.2) |
| F2 | medium | pain.001 check (Py, TS) | Fields that change how money moves were ignored: `PmtMtd = CHK`, an added `IntrmyAgt1`, any unknown element | Fixed by the same closed comparison |
| F3 | medium | revocation lists (Py, TS) | The issuer key was checked at the issuer-chosen `issued_at` and lists had no maximum lifetime: a retired key could sign an empty list current until 2099 | Fixed: the key must be valid at `issued_at` and now; `next_update` at most 24 hours after `issued_at` |
| F4 | low | pain.001 check (Py) | A lone surrogate raised `UnicodeEncodeError` instead of `xml_malformed` | Fixed: characters XML does not allow are rejected before parsing, in both |
| F5 | low | Py vs TS | The strict XML subset differed: NEL and U+FEFF trimming, BOM, non-ASCII names, the declaration grammar, `--` in comments, `]]>` in text, unbound or empty prefixes, duplicate expanded attributes | Fixed: one grammar in the spec (6.2), enforced the same way in both; every differential case now agrees |

Confirmed to hold: amount, currency, account, end-to-end id and envelope tampering; DOCTYPE, CDATA, processing instructions, depth and character references; stale, future, tampered and untrusted revocation lists; an issuer cannot revoke on anyone's behalf; key set windows, compromised keys and checker ids; 31 closed-shape differential cases.
