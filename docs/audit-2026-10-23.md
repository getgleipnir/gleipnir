# Audit: mandate check v0.1 (23.10.2026)

Scope: `spec/mandate.md`, `python/gleipnir-verify/src/gleipnir_verify/mandate.py`, `tests/test_mandate.py`, branch `kya-mandate-spec` @ 57ef600.
Attacks are in `python/gleipnir-verify/tests/test_mandate_audit.py`: each test asserts the safe behaviour, so a failing test is an open finding. Run: `uv run pytest python/gleipnir-verify/tests/test_mandate_audit.py -q` → **43 failed, 30 passed** (passing tests are attacks that are already handled).

## 1. Findings

| ID | Sev | What is broken | Repro (test) | Fix |
|---|---|---|---|---|
| C1 | critical | `authority(company, signer)` gets the signer dict from the mandate itself, including the attacker-chosen `public_key`. A bank that looks signatories up by id (the natural reading of the API and spec §6) accepts a mandate signed with any key. Full forgery: any IBAN, any amount. | `test_C1_*` | Checker must take the authorized **key** from the authority source and compare it to `signer.public_key` itself; `authority()` returns `(source, keys)` not a name. Spec §6: "the signer's key must be one the source binds to that person". |
| C2 | critical | `requested_at` is set by the agent and used as "now" for expiry, `valid_from`, revocation time and period counters. Backdating by one second defeats revocation and expiry. | `test_C2_*`, `test_C2b_*` | Use the checker's clock (`at = now()`), allow small skew; `requested_at` only informational. Spec §5 step 5/6. |
| C3 | critical (for anyone relying on decisions) | `verify_decision()` trusts the key embedded in the decision. Anyone mints a valid-looking "allow". | `test_C3_*` | `verify_decision(d, *, checker_keys)` that pins the bank's key(s); drop the keyless variant or rename it `decision_self_consistent`. |
| H1 | high | No replay protection: the same payment, or the same id with another amount, is allowed again. Spec has no idempotency. | `test_H1_*`, `test_H1b_*` | Spec: payment `id` unique per mandate; checker keeps seen ids (or a `seen(payment_id)` hook) and returns `block: duplicate_payment`. Decision references the first decision. |
| H2 | high | `Checker.spent` defaults to "0 spent": a bank that forgets the counter has **no period limit** (fail-open). | `test_H2_*` | No default: if `max_per_period` is set and no counter is wired → `escalate: period_counter_missing`. |
| H3 | high | `check()` reads the period total but never reserves. Two parallel checks both pass and together exceed the limit. | `test_H3_*` | `reserve(mandate_id, period, amount) -> bool` atomic hook (compare-and-add), released on reject. Spec must say it. |
| H4 | high | `"NaN"`, `"sNaN"` amount → `decimal.InvalidOperation` escapes `check()` (not a `ValueError`). | `test_H4_*` | Strict amount regex `^(0|[1-9]\d*)\.\d{2}$` per currency before `Decimal`. |
| H5 | high | Payee entry without `account` in a signed mandate → `KeyError` in `check()`. | `test_H5_*` | Validate `scope.payees` in `mandate_problem`. |
| H6 | high | One malformed entry in `Checker.revocations` → every `check()` raises. | `test_H6_*` | Validate revocations on load; skip/log bad ones. |
| H7 | high | Non-dict payment (`None`, list, str, int) → `AttributeError` building the decision. | `test_H7_*` | Validate payment shape first; hash only dicts. |
| H8 | high | Float NaN / int > 2^53 anywhere in payment → `FloatDomainError` from JCS inside `check()`. | `test_H8_*` | Catch canonicalization errors → `block: payment_malformed`. |
| H9 | high | Hypothesis fuzzing: `check()` raises on junk input (AttributeError, KeyError, InvalidOperation, FloatDomainError). No "allow" on junk found. | `test_H9_*`, `test_H9b_*` | Wrap `_run` and decision build; every failure returns a signed `block`. |
| M1 | medium | Passkey challenge = bare mandate hash, same shape as the approvals challenge; no domain separation between "approve action" and "sign mandate" on one signing page. | `test_M1_*` | Challenge = SHA-256("gleipnir/mandate/v0.1\n" ‖ mandate_hash). |
| M2 | medium | Payment dated months in the future is checked as of that date. | `test_M2_*` | Same fix as C2 (checker clock, max skew). |
| M3 | medium | Amount format not enforced: `"25000.001"`, `"1e3"`, `"0025000.00"`, `"25000"`, whitespace all accepted; spec says minor units. | `test_M3_*` | Strict per-currency format (ISO 4217 minor units); reject otherwise. |
| M4 | medium | `"0.00"`, `"-0"` payments allowed. | `test_M4_*` | Amount > 0. |
| M5 | medium | IBAN normalization only strips spaces; tabs/dashes from real payloads are blocked (fail-closed, but breaks integration). | `test_M5_*` | Normalize per ISO 13616 (remove all non-alphanumerics), validate mod-97. |
| M6 | medium | Mandate without `status_url` is irrevocable everywhere except at a checker that happens to hold the revocation. | `test_M6_*` | Spec: `status_url` (or a published revocation list) required; checkers must consult it. |
| M7 | medium | Spec doesn't say to reject duplicate JSON keys; parsers disagree (Python last-wins). Parser differential on `amount`. | `test_M7_*` | Spec: I-JSON (RFC 7493), reject duplicates before hashing; ship `parse_strict()`. |
| L1 | low | Non-RFC 3339 timestamps (`09Z`, `09:14Z`, 7-digit fractions) accepted; spec says strict. | `test_L1_*` | Reuse the strict timestamp parser from format.md verifier. |
| L2 | low | `valid_until` before `valid_from` can be issued. | `test_L2_*` | Check in `mandate_problem`. |
| L3 | low | `max_per_period.period` not validated (`"whenever"`). | `test_L3_*` | Allow-list `P1D`, `P7D`, `P1M`. |
| L4 | low | IBAN check digits not validated on issue. | `test_L4_*` | mod-97 on issue. |
| L5 | low | Decision id = 64 bits of payment hash: same id for repeat checks; confirms guesses of payment content. | `test_L5_*` | Random id (ULID). |
| L6 | low | NFC vs NFD names hash differently; authority by company *name* is a string compare. | `test_L6_*` | Spec: NFC for all strings; authority keyed on ids, not names. |

Attacks that **held** (tests pass): signature domain separation (revocation/decision sig as mandate sig), key-type confusion (P-256 text for Ed25519 sig, garbage keys), WebAuthn with empty rp_id/origins (fails closed), passkey sig on payment or revocation (rejected), outsider revocation (ignored), falsy authority on revocation, status_url answers `"Active"`, `""`, `None`, exceptions (all fail closed), non-UTC offsets, negative/Infinity/float amounts, same name with other IBAN, US account with extra fields (fail-closed), non-dict mandate, field order.

## 2. Spec vs code (12 steps)

Order and reason codes match spec §5 for steps 1–12. Divergences:

- Step 5/6 use the agent-supplied `requested_at` (C2) — spec is silent on whose clock; that silence is the bug.
- Bad `requested_at` / bad amount return `mandate_malformed`; spec has no code for a malformed **payment**. Add `payment_malformed`.
- Spec: amounts "with the currency's minor units" — not enforced (M3). Spec: strict RFC 3339 — not enforced (L1).
- Spec §6 says the checker decides authority but not that the **key** must be bound by the source (C1).
- Spec §5 "the checker keeps running period totals" — code makes it optional and fail-open (H2), no reservation (H3).

Missing for a real bank:
1. Idempotency / nonce: payment id uniqueness, duplicate handling (H1).
2. Checker clock and allowed skew (C2).
3. Atomic period reservation and release (H3).
4. Decision verification with pinned bank keys; key rotation (`kid`, validity) for signers, agents and checkers.
5. Revocation distribution: required `status_url` or signed revocation list, cache TTL, offline behaviour (M6).
6. Multi-signature mandates (Gesamtprokura / collective signing) — common in DACH and in bank KYB.
7. ISO 20022 `pain.001` mapping (where the mandate ref and hash travel), and the API shape a PSP exposes.
8. Retention of decisions and mandates (how long, who holds what) and data minimisation.
9. Liability: who bears the loss when an allowed payment was fraud (company vs bank vs checker) — today undefined.
10. PSD2 SCA: how a pre-signed mandate relates to SCA / dynamic linking (and the US equivalent under UCC 4A "commercially reasonable security procedure").
11. Strict JSON rules (I-JSON, NFC, no duplicates) (M7, L6).

## 5. Top 3 before YC (02.11)

1. C1 + C2: bind authority to the key; use the checker's clock. Without these a demo to a bank fails on the first question.
2. C3 + H1–H3: pinned-key decision verification, idempotency, atomic period reservation, no fail-open default.
3. Make `check()` total (H4–H9): strict parsing, every bad input returns a signed `block`; raise coverage to ≥95%.
